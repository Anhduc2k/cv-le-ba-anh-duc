Builder — the editor customers author in

Drag-and-drop editor for landing pages, popups and slide decks, plus the checkout customers sell through.

  • ~40 element types as self-contained plugins — headline, paragraph, button and button group, image, shape, video, gallery, carousel, menu, tabs, accordion, table, countdown, survey, popup, section and group (nested selection, moved and snapped as one). Each declares its own property schema, so a new type ships without touching the canvas core.
  • Form & checkout — typed fields with validation, reCAPTCHA, Vietnamese province / district / ward address pickers, cart, product and quantity selectors, coupons and order bumps, wired to COD, bank transfer, VNPAY, MoMo, ZaloPay, ShopeePay, NAPAS, Stripe and PayPal.
  • Custom code — per-element and per-page HTML / CSS / JavaScript in an embedded editor, with SASS compiled in the browser.
  • Engine architecture — a prototype-based class of roughly 460 methods partitioned by concern: builder operations, getters and setters, mouse and keyboard events, HTML generation, snapping, rollback, attribute mapping and responsive adaptation.
  • Undo/redo as diffed transactions, not state snapshots — a transaction captures the affected elements and their children, then records only what actually changed. History is capped, and acting after an undo truncates the redo branch.
  • Deliver custom-coded landing pages for enterprise clients on the builder's extension model rather than forking it.

Dashboard — where customers run the business current focus

Landing pages, e-commerce, CRM and sales pipeline, tasks, marketing automation, reports, blog and settings — on the live React/Redux dashboard and the Next.js rewrite replacing it.

  • Production dashboard — React 18 in an Nx monorepo: Redux + redux-thunk, React Router 5, REST over axios, i18next, Socket.IO.
  • Rewrite — Next.js 16 App Router, React 19, TypeScript strict, Tailwind v4, organised as three parallel route-group shells (dashboard, auth, full-screen builder) so builder and presenter views escape the dashboard chrome. Deliberately dropped Redux: server state in the data layer, cross-route state in a few contexts, the rest local to the feature.
  • REST API layer — one typed client fanning out to six separate backend products, split per domain. Each needs a different identity header set (store-id, team-id, Owner-Id) and rejects the others at CORS preflight; each also keys off its own store id in a separate ID space, so ids resolve once at bootstrap and are cached.
  • Data tables, the contract every list screen follows — server-side pagination, search debounced at 300 ms, sorting, filters, URL-synced state, and AbortController signals so rapid filter changes cannot race.
  • CRM sales pipeline — Kanban for deals and tasks on @dnd-kit, with list, to-do and forecast views. Card mutations are optimistic with snapshot rollback, and board totals come from server-computed summaries, never summed from the loaded page — the shortcut that silently reports wrong numbers once a pipeline exceeds one page.
  • Lead routing and segmentation — auto-assign rules as a drag-reorderable priority list with nested condition groups and ratio-weighted distribution across staff. The segment builder derives its operators and value-input type from the field.
  • Embedded micro-frontend — a separate flow-editor app in an iframe with origin-validated postMessage both ways for pushing refreshed credentials after a token renewal, kept mounted across navigation so switching pages never reloads it mid-edit.

Identity & SSO LadiUID
  • Hold the JWT in a cookie rather than localStorage, deliberately: the edge middleware, the React app and the embedded legacy AngularJS builder all read one value, so the legacy builder needs no token bridge and signing out in one tab propagates everywhere.
  • Built the full identity surface against the platform's LadiUID service — sign-in, signup with OTP verification, password reset and change, session activity history, sign-out-all-devices — plus TOTP two-factor with a trusted-device list and per-device revocation.
  • OAuth2 with Google and Facebook through a popup bridge relaying the provider's code back via postMessage. The middleware whitelists that path, since the ordinary "authenticated user on an auth route → redirect" guard would otherwise hijack the callback.
