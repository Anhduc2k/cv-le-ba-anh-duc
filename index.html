LadiPage has two sides: the builder customers author their pages in, and the dashboard they run their business from. I maintain the builder engine on my own and contribute to the ground-up rebuild of the dashboard.

Builder engine — sole ownership

  • I was onboarded onto the engine by the developer who owned it. They left about a year ago, and I've run it alone since. New element types, features and production bugs all come to me.
  • Element types are plugins with their own property schema, so I can add one without touching the canvas core. New fields have to stay optional; otherwise pages built on older versions stop loading.
  • Undo/redo works on diffs, not full-state snapshots. Every field I add has to take part in the diff or history breaks.
  • I extend and support the form and checkout stack (validated fields, address pickers, cart, quantity, coupons, order bumps) across nine payment providers. Each one has its own redirect and callback quirks.
  • Wired the AI features into the canvas. Model output becomes real elements on the element tree, so a generated section is still editable afterwards.

Dashboard — platform rebuild

  • The old dashboard put everything through Redux, including state nothing else read. The rebuild drops it: server state stays in the data layer, only genuinely cross-route state goes into context, the rest stays local to its feature.
  • Built the typed API client for six separate backend products. Each wants a different set of identity headers and rejects the extras at CORS preflight, and each has its own store id. Send the wrong id and you get an empty list, not an error, so the mistake looks like missing data.
  • Lists were filtering client-side over one fetched page, so anything past page one was wrong. I wrote the data-table contract every list screen now follows: server-side pagination, debounced search, sorting, filters, state synced to the URL, abortable requests.
  • CRM pipeline totals come from server-computed summaries, not from summing the page in the browser. Card moves apply straight away and roll back if the write fails.
  • The legacy AngularJS builder and the new React app share one session, so the JWT lives in a cookie instead of localStorage. Middleware, React app and the old builder all read the same value. Also built OAuth2 sign-in and TOTP two-factor.
