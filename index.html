Builder — the editor customers author in

Drag-and-drop editor for landing pages, popups and slide decks, plus the checkout customers sell through.

  • The canvas core is the riskiest code in the product — every editing session runs through it, and undo is the feature nobody notices until it loses their work. I designed the ~40 element types as self-contained plugins declaring their own property schema, so a new type never requires opening the core; and built undo/redo as diffed transactions — capture the affected elements and their children, record only what changed — because whole-state snapshots do not hold up on element-heavy pages.
  • Checkout is the one surface where a frontend defect costs the customer money rather than patience. I built the form and checkout stack — validated fields, address pickers down to ward level, cart, quantity, coupons, order bumps — against nine payment providers (COD, bank transfer, VNPAY, MoMo, ZaloPay, ShopeePay, NAPAS, Stripe, PayPal), each with its own redirect and callback behaviour.
  • Per-element and per-page custom HTML / CSS / JavaScript in an embedded code editor, with SASS compiled in the browser, so power users extend a page without leaving the builder.

Dashboard — where customers run the business current focus

Landing pages, e-commerce, CRM and sales pipeline, tasks, marketing automation, reports, blog and settings — on the live React/Redux dashboard and the Next.js rewrite replacing it.

  • The previous dashboard routed every piece of state through Redux, paying boilerplate for state never actually shared. Rebuilding it in Next.js 16 App Router, React 19, TypeScript strict and Tailwind v4, I dropped Redux entirely: server state in the data layer, only cross-route state in context, the rest local to its feature.
  • Six backend products, each demanding a different identity header set and rejecting the others at CORS preflight — each keyed to its own store id, where the wrong one returns an empty list instead of an error, so a mistake looks like "no data" rather than a bug. I built one typed client resolving the right identity per target.
  • Lists were sorting and filtering client-side over a single fetched page, so results silently went wrong past page one. I defined the contract every list now follows: server-side pagination, debounced search, sorting, filters, URL-synced state, and AbortController so fast filter changes cannot race. One contract retired the bug class across every list in the product.
  • Board totals summed from the loaded page look right in a demo and go wrong once a pipeline exceeds one page — and sales teams reconcile them against real money. I took totals from server-computed summaries, and made card mutations optimistic with snapshot rollback so dragging a deal feels instant without leaving the board lying on a failed write.
  • Plain round-robin ignores that staff have different capacity, so I built auto-assign as a drag-reorderable priority list of rules over nested condition groups, with ratio-weighted distribution across staff. The segment builder derives its operators and value-input type from the field itself.
  • Conversion runs long enough that a held-open request dies in the browser, so the HTML→LadiPage converter polls with staged backoff instead. When the backend returns no risk analysis, the client derives the likely-diverging parts from the converted output itself.
  • Embedding a separate editor normally means reloading it on every navigation and losing in-progress work. I mounted the flow-editor application in an iframe kept alive across dashboard navigation, with origin-validated postMessage both ways so refreshed credentials can be pushed in after a token renewal.

Single sign-on across the product family LadiUID
  • The legacy AngularJS builder and the new React app had to share one session, or users would be asked to sign in twice inside the same product. I built auth against the platform's LadiUID service — sign-in, OTP signup, password reset, OAuth2 Google and Facebook, TOTP two-factor — and kept the JWT in a cookie rather than localStorage so the edge middleware, the React app and the embedded legacy builder all read one value, with no token bridge and sign-out propagating across tabs.
  • Wrote the token-renewal interceptor — a 401 / 498 / 503 triggers one silent renewal and a single retry, with an opt-out flag so the auth endpoints themselves cannot recurse through it. OAuth callbacks arrive through a popup bridge relaying the provider's code via postMessage, on a path the middleware must whitelist or the "authenticated user on an auth route → redirect" guard hijacks the callback.
